# Bot roadmap — sequential PRs, each independently shippable

We deliberately split the rebuild into five PRs so each lands and
gets validated before the next starts. Bigger combined PRs took
weeks and broke working flows mid-rewrite.

## PR 1 — Persona presets, hook engineering, spam triage docs ✅ this PR

Goal: stabilize the account today, make AI replies dramatically
sharper without changing the bot's command surface.

- `bot/SPAM_TRIAGE.md` — emergency checklist (read first if ER
  is dropping)
- `bot/personas/PRESETS.md` — six preset persona dossiers, each
  with bio + style + 10 example tweet→reply pairs
- `bot/src/persona/presets.js` — code-loadable preset registry
- `bot/templates/peak-v2-hooks.md` — peak template set, every
  line rewritten so it engages thread-readers (not just the
  original author)
- `bot/src/persona/persona.js` patch — system prompt now
  includes audience-aware framing and hook techniques
- `bot/src/telegram/bot.js` patch — `/new` persona step shows
  preset buttons (instant pick) + custom + skip; new `/menu`
  command with main menu inline keyboard

User experience after PR1:

- Type `/new` → name → keywords → templates → **persona buttons
  appear**: Cycle Veteran / DeFi Quant / SOL Degen / Macro
  Analyst / Builder / Contrarian / ✏ Custom / ⏭ Skip
- One tap = full persona with 10 examples loaded
- Replies generated by AI use audience-hook techniques out of
  the box

## PR 2 — Sectioned UI, `/menu` deep nav, granular settings panel

Goal: replace command memorization with a navigable menu.

- `/menu` opens main menu (Campaigns / Settings / Personas /
  Posts / Diagnostics) — already stubbed in PR1
- Per-section sub-menus with all current settings exposed as
  inline buttons + value-edit prompts
- Settings panel covers: pacing, sleep window, filters
  (minLikes, minFollowers, langs, skipReplies, skipRetweets),
  persona swap, template hot-reload
- All existing slash commands keep working (backward
  compatible)

Estimate: 1-2 days of work, ~400 lines.

## PR 3 — Trend extractor (free)

Goal: surface what's trending in the user's existing feed,
zero external API.

- `bot/src/scout/trends.js` — keyword frequency tracker over
  rolling 6h / 24h windows
- Pulls data from the HomeTimeline scan that runner.js already
  does — no new scraping, no cost
- Spike detection: term mentioned ≥N times AND ≥X% above
  baseline → flagged
- New `/trends` command: returns top 5 spikes with example
  tweets and one-line "why this matters" generated by AI in
  user's persona voice
- Stored in SQLite, not in-memory, so the trend window
  survives restarts

Estimate: 1 day, ~250 lines.

## PR 4 — Auto-post engine (the actual fix for low ER)

Goal: regular original posts in user's voice, drafts approved
manually, posted via existing CreateTweet capability.

- `bot/src/posts/draft.js` — generates 3 candidate drafts from a
  trend signal (PR3 output), via OpenAI in user's persona voice
- Telegram preview UI: each draft as a separate message with
  inline buttons [✅ Post] [🔁 Regenerate] [✏ Edit] [❌ Skip]
- `bot/src/posts/scheduler.js` — anti-bot pacing for posts:
  3-10 per day, irregular spacing (30min-4h gaps), respects
  sleep window
- `/post <text>` for manual one-shot posts
- `/draft` to generate fresh candidates on demand
- `/queue` to inspect what's scheduled, reorder, cancel
- Per-day post counter + log table in SQLite

Estimate: 2-3 days, ~600 lines + UI.

## PR 5 — Engagement loop hooks

Goal: turn every successful reply into a content opportunity.

- When a bot-sent reply receives ≥5 likes within 4h, mark it
  as a "hit"
- For hits, automatically generate a draft post that develops
  the same idea into a top-level tweet — uses the original
  reply as seed
- Send the draft to Telegram for approval (same UI as PR4)
- Per-week digest: which replies hit, which template tags hit
  most often, which authors gave the highest engagement — for
  manual tuning of templates and follow targets

Estimate: 1-2 days, ~300 lines.

## What we're explicitly NOT building

The following ideas were considered and rejected for cause —
documented here so they don't re-emerge as well-meaning suggestions
in future planning:

- **Whale-scout with mass cold DM** — see chat history. X bans
  this pattern within weeks. Conversion is statistically zero
  post-2024 drainer waves. Replaced by reply-first + content-first
  flywheel above.
- **Open-DM detector** — no clean technical path that isn't TOS
  violation. Not a useful filter even if built (open DMs in 2026
  correlate with low-quality targets, not high).
- **Wallet-to-handle linking beyond self-disclosed bio** — that's
  doxing. Self-disclosed (user wrote address in their own bio)
  is the only acceptable signal.
